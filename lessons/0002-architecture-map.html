The Architecture Map

One token's path through the SPP model, and the four places your replication changes it.

SPP changes no weights and no layers. Everything it does is in what goes into a standard Llama-style decoder: which documents (data mixing), which tokens (tokenization), which positions (RoPE), and who can see whom (attention mask). This lesson is the map. The next lessons go deep on each of those four points.

2 · The forward pass

Shapes use Levanter's named axes. In llama.py, a decoder layer is literally the five lines inside the dashed box below.levanter llama.py · LlamaDecoderLayer Stages marked in orange are the ones SPP changes.

Data mixture → documents data mixingdocs Choose which documents fill each batch, in what proportions, and whether they're packed or padded.
↓
Tokenizer tokenization[position] int Text → integer IDs using byte-level BPE. Special tokens (EOS, <assistant>) are single IDs the tokenizer never produces from ordinary text.
↓
Embedding lookup[position, embed] Row E[id] of a V × dmodel matrix. No position information gets added here. That was GPT-2's approach, and modern models don't do it.
↓
× 28 decoder layers
RMSNorm → q, k, v projections[position, heads, head_size] Pre-norm: normalise first, then project. GQA: 24 query heads share 8 key/value heads (3 per group). head_size = 3072/24 = 128.
↓
Rotate q and k by position RoPEneeds pos_ids Each (q, k) is rotated by an angle proportional to its position ID. That makes q·k depend on relative distance. v is not rotated.
↓
Scores, mask, softmax, ·v attention mask[position, key_position] Scores are qkᵀ/√d. Blocked pairs are set to −∞ before the softmax, so they get exactly zero weight. Normally the mask is just "causal", but it can be any boolean matrix.
↓
o-projection, + residual[position, embed] x = x + attn(norm(x))
↓
RMSNorm → SwiGLU MLP, + residual[position, embed] down( silu(gate(x)) * up(x) ). This is where most of the parameters and FLOPs are. Each token is processed independently, with no cross-token mixing.
↓
Final RMSNorm → LM head (tied)[position, vocab] Logits = h · Eᵀ, reusing the embedding matrix. So the new <assistant> token's row is both its input and its output vector.
↓
Cross-entropy × loss weights loss maskscalar Position i predicts token i+1. Each position's loss is multiplied by a weight in {0, 1}, which decides what the model is trained to generate.

Two kinds of masking. The attention mask controls what a token can see. The loss mask controls what the model is trained to produce. They're independent, and SPP uses both. People mix them up constantly, so keep them separate.

3 · What SPP feeds in

Here's a toy version of _make_spp_sample from the SPP dataloader.spp_dataloader.py A document The cat sat on the mat gets a 2-token reflection r1 r2 inserted at n = 3, preceded by <assistant>:

index012345678
tokenThecatsat<asst>r1r2onthemat
predictscatsat<asst>r1r2onthemat…

The code makes three adjustments, each one quoted from the dataloader's docstring:

  1. Loss mask: "Mask the pre-<assistant> position … so <assistant> is never an NTP target." The model never learns to start a reflection on its own.
  2. Attention mask: "blocks post-context tokens from attending to the <assistant>/reflection region."
  3. Position IDs: "Alias post-context position IDs back to the reflection insertion point so that RoPE distances are identical to inference."

4 · Check your map

Exercise 1Write the 9 position IDs for indices 0–8 in the toy example. Use the rule: reflection tokens continue counting from n, and post-reflection tokens alias back to start at n.

0 1 2 | 3 4 5 | 3 4 5. Now "on" (index 6, pos 3) is 1 position from "sat" (pos 2), exactly as if the reflection were never there. That's what happens at inference, where no reflections exist.

Exercise 2Which key indices can the query at index 6 ("on") attend to?

Causal (≤ 6), minus the SPP block on 3–5. The continuation is conditioned only on the original document.

Exercise 3Which prediction has its loss weight set to 0?

The model should never learn to emit <assistant> spontaneously in the middle of text. <asst> → r1 is trained: given the marker, produce the reflection.

Exercise 4The mask already hides the reflection from later tokens. Why alias their position IDs as well?

Masking removes the reflection's content, but without aliasing, "on" would sit at position 6 and see "sat" at distance 4 instead of 1. RoPE would make attention to the prefix behave differently from inference. Masking handles what is seen. Aliasing handles where it appears to be.

Exercise 5Where does RoPE act in this model?

RoPE rotates q and k (not v) in every layer, using the position IDs. That's why SPP can change positions with a single input array and no architecture change.

Exercise 6In this pipeline, what is data mixing responsible for?

In SPP, mixing decides the 80.6% compact (packed) vs 19.4% annotated (one doc per padded window) streams, which documents get reflections, and when (token zero vs midtraining).SPP Table 1
