The 6ND Budget

How to cost out a 1.4B-parameter, 20-tokens-per-parameter run before it starts, using one multiplication.

Your next Marin milestone after the SPP replication is a 1.4B model at 20 TPP on TPUs. By the end of this lesson you'll be able to work out, on a napkin, how many FLOPs that run needs, how many chip-hours it costs, and how it compares to the largest SPP runs. Every scaling-law paper you read assumes you can do this.

1 · Where the 6 comes from

Almost all of a transformer's compute is matrix multiplies. Multiplying an N×P matrix by a P×M one costs 2NPM FLOPs: one multiply and one add for each of the NPM products.scaling book §Forward and reverse FLOPs

Read it as a weight matrix W of shape P×M (so PM parameters) acting on N tokens:

  • Forward: Y = XW costs 2 FLOPs per parameter per token.
  • Backward: you need two gradients, ∂L/∂W = Xᵀ·∂L/∂Y (to update the weights) and ∂L/∂X = ∂L/∂Y·Wᵀ (to keep backpropagating). Each is another matmul of the same size, so that's 4 more.

You've written autograd, so you've seen this already: the backward pass of a linear layer does two matmuls. Add them up and every parameter costs 6 FLOPs per training token:scaling book

C ≈ 6 · N · D C = training FLOPs · N = parameters · D = training tokens

Inference is the forward pass alone, so it costs 2N per token. That's why training is about 3× inference per token.

What 6ND leaves out. (1) Attention's QKᵀ and ·V FLOPs. They grow with sequence length T, and only dominate once T > 8·dmodel. For a 1.4B model (dmodel around 2048) that's past roughly 16k tokens, far longer than a typical pretraining context.scaling book §attention cost (2) Rematerialisation (gradient checkpointing) reruns parts of the forward pass, which pushes the cost toward about 8ND.scaling book §Gradient checkpointing (3) What counts toward N? Kaplan et al. counted only non-embedding parameters,Kaplan 2020 so check which convention a paper (and Marin's "1.4B") uses. That's lesson 2.

2 · Where "20 tokens per parameter" comes from

Chinchilla (Hoffmann et al., 2022) trained more than 400 models and found that, for a fixed compute budget, parameters and tokens should grow at roughly the same rate. Their flagship had 70B params trained on 1.4T tokens, matching Gopher's compute with a model 4× smaller.Hoffmann 2022 1.4T ÷ 70B = 20. That ratio became the default "compute-optimal" TPP (tokens per parameter).

"Compute-optimal" means the lowest loss for a given training compute. Inference cost isn't part of it. That's why modern models go far past 20: Llama 3 70B saw 15T tokens,scaling book §LLaMA 3 which is about 214 TPP. At 20 TPP, your 1.4B run is sized as a clean scaling-law point, not a product model.

3 · From FLOPs to wall-clock

Hardware never reaches its peak. MFU (model FLOPs utilisation) is the fraction of peak FLOPs/s that goes into the model's actual 6ND math. The scaling book uses 40% as a reasonable assumption.scaling book

time ≈ C / (chips · peak FLOPs/s per chip · MFU)

Worked example: Llama 3 70B

C = 6 × 70e9 × 15e12 = 6.3e24 FLOPs. On a full v5p pod (8,960 chips) at 40% MFU: 6.3e24 / (8960 × 4.59e14 × 0.4) ≈ 3.8e6 s ≈ 44 days.scaling book §LLaMA 3

4 · Your turn: cost out the 1.4B run

Use a scratch pad or a Python REPL, not this page. Enter answers like 2.8e10. Anything within 3% counts.

Exercise 1At 20 TPP, how many training tokens D does the 1.4B model see?

D = 20 × 1.4e9 = 2.8e10 = 28B tokens.

Exercise 2Total training compute C for the run (ignore attention and remat)?

C = 6 × 1.4e9 × 2.8e10 = 2.35e20 FLOPs. Note that at fixed TPP, C = 6 · 20 · N², so compute grows with the square of model size.

Exercise 3On TPU v5e at 40% MFU, how many chip-hours is that?

Effective per-chip rate = 1.97e14 × 0.4 = 7.88e13 FLOPs/s. 2.352e20 / 7.88e13 ≈ 2.98e6 chip-seconds ÷ 3600 ≈ 829 chip-hours.

Exercise 4If it runs on 64 v5e chips with perfect scaling, what's the wall-clock time?

829 / 64 ≈ 13 hours. So this run is cheap. What will actually limit you is the cost of the ablations and evals around it.

Exercise 5The SPP paper's largest experiments reach about 3B params and 500B tokens.Minder 2026 How many times the compute of your 1.4B / 20 TPP run is that?

6 × 3e9 × 5e11 = 9e21 FLOPs. 9e21 / 2.352e20 ≈ 38×. That's about 167 TPP, deep in the "over-trained" regime. Worth asking: the paper reports SPP's advantage grows with pretraining budget, so what would you expect at 20 TPP?

5 · Check your understanding

Why is the training constant 6 rather than 2?

Backward needs two matmuls per weight: one for ∂L/∂W and one for ∂L/∂X. The optimizer update is elementwise, about O(N) per step rather than per token, so it rounds to zero.

Marin goes from 1.4B to 2.8B params, keeping 20 TPP. Training compute multiplies by:

At fixed TPP, D scales with N, so C = 6·N·(20N) ∝ N². Doubling N gives 4× the compute.

MFU is best defined as…

MFU counts only the model's 6ND math. Recomputed (remat) FLOPs don't count, which is why remat lowers MFU even though the chip is just as busy.

When does ignoring attention FLOPs stop being safe?

Attention-to-matmul FLOPs ratio is about T / (8D). Long-context training (e.g. Kimi's 1M context) is where this starts to dominate.

Stretch · Measure your own Mac

Peak numbers are marketing. Measure what you actually get, which is the first step of any performance work. Run this with pip install mlx:

import mlx.core as mx, time
n = 4096
a = mx.random.normal((n, n)).astype(mx.bfloat16)
b = mx.random.normal((n, n)).astype(mx.bfloat16)
for _ in range(3): mx.eval(a @ b)          # warm up
iters = 50
t = time.perf_counter()
for _ in range(iters): mx.eval(a @ b)
dt = time.perf_counter() - t
print(f"{2 * n**3 * iters / dt / 1e12:.2f} TFLOP/s")   # 2NPM, from §1

Then plug your number into the formula. How long would the 1.4B run take on your laptop at 100% MFU? What about a 10M-param char-level model on 100M tokens? The second one is your first from-scratch training target.
